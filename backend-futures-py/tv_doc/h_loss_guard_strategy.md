# 第二帳號 H1 混合策略

目的：第二帳號不跟 H1 同步進場，而是監控第一帳號的 H1 持倉。

第二帳號有兩種模式：

```text
1. guard_reverse：第一帳號 H1 看錯且虧損擴大時，第二帳號反向護欄
2. profit_follow：第一帳號 H1 已經賺錢且短週期支持時，第二帳號順向跟進
```

這個版本只發 Discord 進出場訊號，不會自動下單。

## 使用資料

- `h_trade.csv`：讀取第一帳號最新 H1 持倉方向與進場價
- `webhook_data_1min.csv`：讀取最新現價，計算單口浮動點數
- `webhook_data_3min.csv`
- `webhook_data_5min.csv`
- `webhook_data_10min.csv`
- `webhook_data_15min.csv`
- `mxf_value.csv`：讀取籌碼方向與趨勢

## 核心流程

```text
第一帳號 H1 已進場
第二帳號空手等待

如果第一帳號 H1 單開始明顯虧損
且多週期/MXF 確認 H1 方向可能看錯
第二帳號進反向單

如果第一帳號 H1 單已經獲利
且 1/3/5 分短週期支持 H1 方向
第二帳號順向跟進 1 口

第二帳號進場後
使用自己的停損、停利、回吐規則出場
```

## 口數同步

第二帳號會跟第一帳號 H 當下口數同步，最多 2 口。

```text
第一帳號 H 是 1 口 -> 第二帳號訊號 1 口
第一帳號 H 是 2 口 -> 第二帳號訊號 2 口
```

如果反向護欄一開始就是 2 口，就不再額外加碼，避免變成 3 口。

例子：

```text
第一帳號 H1 多單虧損擴大
護欄確認偏空
第二帳號發空單進場訊號
```

```text
第一帳號 H1 空單虧損擴大
護欄確認偏多
第二帳號發多單進場訊號
```

## 單口計算

所有浮動損益都用單口點數計算，不乘以實際口數。

```text
多單浮動 = 最新 close - 進場價
空單浮動 = 進場價 - 最新 close
```

## 模式一：反向護欄進場條件

第二帳號只有在第一帳號 H1 單看錯時才反向進場。

### 1. 硬觸發

第一帳號 H1 單口浮虧達 480 點：

```text
H1 unrealized_points <= -480
```

第二帳號直接進反向單。

### 2. 多週期失效

第一帳號 H1 單口浮虧達 180 點，且至少 3 個週期失效：

```text
H1 unrealized_points <= -180
invalid_timeframes >= 3
```

第一帳號多單失效條件：

```text
close < MA_N200
BBR < 0.45
```

第一帳號空單失效條件：

```text
close > MA_P200
BBR > 0.55
```

### 3. MXF 籌碼反向確認

第一帳號 H1 單口浮虧達 180 點，至少 2 個週期失效，且 MXF 籌碼也反向。

第一帳號多單看錯：

```text
mxf signal = bear
mxf trend = death
```

第一帳號空單看錯：

```text
mxf signal = bull
mxf trend = gold
```

## 第二帳號出場條件

第二帳號進反向單後，先 1 口進場，確認有跑出方向才加第 2 口。

## 第二帳號加碼條件

初始反向進場只進 1 口。

符合以下條件才加第 2 口：

```text
第一口浮盈 >= 180 點
且 1/3/5 分鐘至少 2 個週期支持第二帳號方向
```

第二帳號多單的短週期支持：

```text
close > MA_N200
BBR > 0.50
```

第二帳號空單的短週期支持：

```text
close < MA_P200
BBR < 0.50
```

加碼訊號：

```text
第二帳號加碼訊號：多單/空單 加 1 口
```

## 第二帳號出場條件

### 1. 停損

加碼前，第一口停損：

```text
second unrealized_points <= -220
```

加碼後，若第一口浮盈跌回 80 點以下，全部出場：

```text
first_leg_unrealized_points <= 80
```

### 2. 停利

停利用第一口浮盈判斷：

```text
second unrealized_points >= 450
```

### 3. 回吐保護

如果第二帳號曾經賺到 220 點以上，但後來回吐到只剩 120 點以下：

```text
max_favorable_points >= 220
current_unrealized_points <= 120
```

就出場。

### 4. 第一帳號 H1 換單

如果第一帳號 H1 最新持倉已經換成另一筆單，第二帳號反向單的前提結束，因此出場。

## 模式二：順向跟進條件

順向跟進只在第一帳號已經賺錢後才會啟動，不會跟第一帳號同時進場。

進場條件：

```text
第一帳號 H1 單口浮盈 >= 240 點
且 1/3/5 分鐘至少 2 個週期支持 H1 方向
```

順向跟進不加碼；口數跟第一帳號 H 當下口數同步，最多 2 口。

出場條件：

```text
第一口浮虧 <= -160 點，出場
第一口浮盈 >= 800 點，停利出場
第一帳號 H1 換單，出場
```

## 目前不做的事

- 不自動下單
- 不讓第二帳號跟 H1 同步進場，順向模式必須等第一帳號已有浮盈
- 不用 2 口放大損益
- 不在第二帳號已有部位時重複進場

## 目前回測摘要

可用 1 分鐘資料中，護欄觸發到 4 次反向進場機會。

原先測試的參數：

```text
停損 180 點
停利 300 點
回吐：曾賺 220 點，回到 120 點出場
```

結果：

```text
合計 -188 點
勝率 1 / 4
```

問題是停損 180 點太緊，5/12 與 5/14 兩筆原本後來會轉正的反向單被先洗出場。

固定 1 口參數：

```text
停損 220 點
停利 450 點
回吐：曾賺 220 點，回到 120 點出場
```

在目前可回測樣本中：

```text
合計 +699 點
勝率 3 / 4
最差 0 點
```

目前採用保守加碼版：

```text
初始 1 口
第一口浮盈 >= 180 點
1/3/5 分鐘至少 2 個週期支持
加第 2 口
```

在目前可回測樣本中：

```text
合計 +879 點
勝率 3 / 4
最差 0 點
```

資料樣本仍偏少，這組參數不是最佳化結論，只是比固定 1 口補償更多，也比一開始直接 2 口保守。
