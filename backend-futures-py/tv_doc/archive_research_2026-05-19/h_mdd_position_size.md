# H1 MDD 口數計算

更新時間：2026-05-15 16:54:40 CST

## 策略規則

14 萬資金帳號：

- 基本口數：1 口
- 加碼門檻：目前 MDD 達 1750 點
- 加碼口數：2 口
- 減碼條件：目前 MDD 低於 1000 點後回到 1 口

## MDD 定義

MDD 是資金曲線從高點回落到目前位置的回撤。

```text
目前 MDD = 歷史最高 equity - 目前 equity
```

這裡用點數理解：

```text
目前 MDD 點數 = 歷史最高點數 - 目前累積點數
```

如果目前累積點數回到歷史最高點，MDD 就是 0。

## 單口計算原則

MDD 一律用單口點數計算，不因為實際下 2 口就把損益乘以 2。

原因是這套策略的 MDD 來源是單口回測值，口數控制只是根據單口 MDD 決定要下 1 口或 2 口。

程式內 `h_trade.csv` 的 `pnl` 欄位也是單口 PnL：

```text
多單 pnl = (出場價 - 進場價) * 10
空單 pnl = (進場價 - 出場價) * 10
```

即使實際交易 `quantity = 2`，MDD 仍然只用上面的單口 pnl 來累計。

`quantity` 欄位只用來記錄實際下單口數，不參與 MDD 放大。

## 目前計算結果

```text
起始 equity = -2300 點
歷史最高 equity = 0 點
目前 equity = -2300 點

目前 MDD = 0 - (-2300)
目前 MDD = 2300 點
```

換成程式內 PnL 單位：

```text
POINT_VALUE = 10
目前 equity PnL = -2300 * 10 = -23000
目前 MDD PnL = 2300 * 10 = 23000
```

## 目前口數判斷

```text
目前 MDD = 2300 點
加碼門檻 = 1750 點

2300 >= 1750
所以目前下一筆進場口數 = 2 口
```

如果下一個訊號是多單，且多單訊號當下最新 close 是 40732，會先結算虛擬空單：

```text
虛擬空單進場 = 41966
虛擬空單出場 = 40732
單口獲利 = 41966 - 40732 = 1234 點

原本 MDD = 2300 點
更新後 MDD = 2300 - 1234 = 1066 點
```

再判斷新多單口數：

```text
更新後 MDD = 1066 點
加碼門檻 = 1750 點
減碼門檻 = 1000 點

1066 < 1750，但仍 >= 1000
如果加碼狀態已開啟，新多單進場口數仍維持 = 2 口
```

## 之後怎麼回到 1 口

如果後續平倉累積獲利讓 MDD 低於 1000 點：

```text
目前 MDD = 999 點
```

這時候加碼狀態關閉，下一筆回到 1 口。

範例：

```text
起始 MDD = 2300 點
後續累積已實現獲利 = 1301 點
目前 MDD = 999 點
下一筆 = 1 口
```

如果只賺回一部分：

```text
起始 MDD = 2300 點
後續累積已實現獲利 = 1234 點
目前 MDD = 1066 點
下一筆仍然 = 2 口
```
